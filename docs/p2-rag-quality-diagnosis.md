## 3. 指标口径

- 文档级 Recall@5：在 45 条可回答问题上取宏平均。先取前五个 chunk 对应的文档 ID，再在每题内去重，与预期文档集合求交。重复文档仍会占原排名槽位；不衡量答案 chunk 的召回。
- MRR@5：同样仅平均这 45 条，取前五个位置中第一个预期文档的倒数排名；不先去重重排。
- 历史“误拒答 16/45”：由 fixture `answerable=true` 与结果 `refused=true` 交集计算。它是按该数据集标注的标准拒答数，不是经过新人工逐题确认的模型内在错误率。
- 无答案拒答率：5 条 `answerable=false` 中按严格拒答分类器判定的比例。正常“不允许/不能/不会”业务答案不是资料不足拒答。
- 关键事实命中：`RagEvaluationAnswerChecker` 统一大小写、去标点/空白后做短语包含检查，再按全部结果的命中数/事实总数聚合；不是语义正确率，不自动理解否定、同义表达和跨片推理。另有禁止结论检查，不能把短语命中单独当质量保证。
- 引用有效率：全部合法引用总数/引用总数；没有引用时实现返回 1.0。48/48 不代表所有答案都有引用或每句被证据支持。
- Relevancy / FactChecking 是额外模型 Judge，历史均值 0.72/0.52，不是人工准确率；本轮不执行 Judge。Token 汇总包括回答和 Judge，不代表纯回答开销。
- 硬门禁检查完整执行、异常、越界、引用、关键错误、Recall 回退和清理；没有对 16/45 过度拒答或 53.06% 事实命中设硬门禁。因此历史 gate passed 不能解释为回答质量已达标。

逐项计算位置：`RagEvaluationMetrics`、`RagEvaluationRefusalClassifier`、`RagEvaluationAnswerChecker`、`RagEvaluationGate`。独立核算结果见比较报告，不覆盖原 JSON。

## 4. 拒答分类器是否误伤正常否定？

分类器使用整段锚定的受控句式，不是发现“不能/不允许”就打拒答标签。本轮确认全部 16 条历史 answer 严格等于“资料不足，无法确认。”，均 0/0 引用、error=null；因此没有证据表明这 16 条是正常否定被错误统计。保存的是后处理结果，不能反推 rawText。

新增 `RagEvaluationRefusalBoundaryTest` 用受控文本验证六种正常否定、解释拒答规则、固定拒答、夹带无依据否定、问题复述边界。文本是测试探针，**不是本轮真实模型答案**。仍可能存在未覆盖语言表达，不宣称分类器对任意文本完美。

`isolation-005` 不在 16 条中：历史答案是固定句加原问题复述，refused=false。不能为提高安全拒答率把它强行改标。普通答案不会被 `RagAnswerService.completeFromDocuments` 改成固定拒答；它保留 answer 并筛选引用。净化器未发现主动生成固定拒答的分支，但没有 rawText，仍不能逐题排除内容被净化删除。

## 6. 为什么本轮不直接改阈值、排序或 Prompt？

3 条关键片段缺失均在当前阈值以下，尚无证据说明 `diversifyByDocument` 错误丢弃已合格的答案片段。全局降低到 0.16 可能引入无答案/干扰语料，不能用 3 条受益样本证明其余 47 条不退化。单文件断句存在，但延长 chunk 会触及固定 embedding 的 128 token 上限；邻片补全也需要保留同租户/知识库/ready 版本与输入预算。

11 条 E2 不是 11 条已证实的 Prompt bug；稳定版已有提示词澄清，缺少新真实基线和 rawText，继续叠加措辞无法建立因果。先保存未来实际证据链再决定修复，不取消拒答、不降门禁、不替换模型。

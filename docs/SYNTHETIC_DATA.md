# 新公开快照的合成数据边界

本页仅描述 2026-10-26 新快照。旧发布仓库与原开发仓库没有修改，也未对任何现有数据库执行 SQL。

## ERP 与会话 seed

保留两份初始化 SQL 的 36 条结构语句；不沿用旧业务/联系人样例行。`business-data.sql` 的 21 张业务表分别使用一行新造合成记录，企业/客户/供应商/产品/人员统一使用 `SYNTH-*`，业务编号使用 `*-DEMO-001`。数量、金额、日期为新设定的演示常数，不代表真实交易、库存、物流、供应商或客户。

`conversation-billing-schema.sql` 仅初始化合成租户、用户、演示套餐、账户、演示价格及原有应用 Tool SQL 定义。不迁入旧聊天内容、账单、交易或 Token 用量样例。应用 Tool SQL 是表名、参数模板与功能描述，不是企业查询结果。演示价格不是供应商实际价格，也不是收费授权。

租户为 `ENT001 / SYNTH-TENANT-001`，联系人为 `SYNTH-CONTACT-001`，电话为不可拨号的 `DEMO-PHONE-001`。UI 中 ENT002 仅保留明确的合成标签，新的最小 SQL seed 没有为它建立业务记录。身份 Header 仍不是生产认证。

## 测试 Fixture

- Java、Python 网关的 Fixture 是本地桩请求/响应和人工构造的断言数据；不连接企业系统。两处测试文件中的公司样例改为显式“合成客户-001”，对应输入和精确预期一起替换，断言行为不变。
- `src/test/resources/rag-eval/v1/documents/` 的六份来源材料均是本项目技术规则的人工测试描述，含一份隔离干扰材料；不是企业制度或外部权威资料。
- 固定 RAG cases 与 diagnostics reconstruction 是已有公开合成评测/离线重建 Fixture，保留其金标、字节身份和断言。重建不等于历史真实请求抓包，不能据此推导新模型质量改善。
- 图表测试数据仅为人工表格/图表协议样例；不附带真实客户、员工、手机号或财务数据。

本次手机号、用户主目录与数据候选静态检查不读取真实 `.env`，不保存命中原文。模型 Tokenizer 的官方词表和开源许可中的作者/机构名称不是本项目业务联系人记录；不得为净化词表而破坏固定资源身份。

两份 SQL 已由既有初始化器路径参与离线回归；本次没有启动 MySQL/PgVector，不将 Mock 初始化器测试称为真实数据库导入验收。

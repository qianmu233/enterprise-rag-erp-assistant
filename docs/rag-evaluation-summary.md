整理日期：2026-10-10（Asia/Shanghai）。P2 功能开发已结束，本文记录已有三轮真实评测与当前实现的限制；整理过程中没有重新执行评测，也没有修改历史报告。

本项目是面向企业知识库与 ERP 查询场景的工程实践，**不宣称达到生产级问答质量**。三轮评测仅验证 knowledge RAG 链路，不构成 ERP Tool Calling、图表、认证或整个系统的真实端到端验收。

## 修复过程与可验证结论

第一轮最终空回答为 25/50，但报告没有保存原始模型输出，不能追溯每条空回答的确切原因。代码审查发现重复/末尾答案标记、旁白前缀与 `accepted=false` 同名业务文本的误删风险，随后增加保守净化边界测试与空回答元数据日志。

第二轮仍有 22/50 空回答。根据该轮诊断记录的人工核对，这 22 条均为 `SANITIZED_EMPTY`：原始文本非空，marker 数为 1，finish reason 为 stop。这说明在当前净化分支中，标记之后没有非空正文；没有保存原始正文，因此不能重建标记前的具体回答。

知识专用系统提示随后取消答案 marker 要求，改为直接输出完整用户可见正文、禁止内部执行旁白，并统一固定拒答句。ERP 的 Tool Calling / marker 协议与净化器 fail-closed 机制保持不变。第三轮观测到空回答降为 0/50、事实短语命中率升至 53.06%、无答案拒答为 5/5。

这些变化解决了本评测集中的输出可用性问题，没有通过返回不可信标记前原文、绕过证据约束、放宽租户隔离或错误结论校验提高指标。

## 如何解释指标

### 文档级 Recall 不等于分片级证据充分

当前 Recall@5 在可回答用例上计算：取报告前五个分片对应的文档 ID，去重后与预期文档 ID 比较，再对用例求平均。MRR@5 是第一个预期文档出现位置的倒数均值。知识模式最多向上下文提供 8 个合格分片，报告只映射前 5 个文档 ID。

同一文档可能有多个分片。召回产品手册的模式说明，不代表同时召回了上传格式或大小上限；文档 ID 命中不能证明模型收到完整答案段落。现有 JSON 不包含实际分片正文、完整模型输入或分片级答案覆盖标注，不能把高 Recall 当作模型已经拥有充分证据。

此外，检索资格过滤后的结果会优先分散文档来源。在仅 5 份目标文档的评测中，文档 ID 覆盖较容易达到较高水平；这会限制 Recall@5 对大语料检索能力的代表性。当前实际实现仍是向量相似度搜索与确定性过滤/选取，没有 Hybrid Search 或语义 Rerank。

### 引用有效率不等于回答都有引用

引用有效率统计“通过校验的引用编号 / 输出的引用编号”。第三轮有 28/50 条回答输出引用，累计 48 个编号，48 个均通过校验；其余回答无引用，不会因为没有引用而降低这个比例。实现中总引用数为零时，该指标按 100% 返回。

编号属于本轮分片只证明引用身份合法，不能单独证明回答忠实于分片。拒答不带引用也不是检索为空的证明，不能以 100% 引用有效率宣称引用覆盖率或事实一致性达到 100%。

### 关键事实命中与 Judge 的限制

关键事实指标通过归一化后的短语匹配计算，统计全部用例的关键事实，包括无答案用例的“资料不足”。第三轮为 52/98，即 53.06%；它不是可回答问题的语义准确率。正确的同义表述可能未命中短语，命中短语也不能替代错误结论和证据一致性检查。

相关性及事实一致性 Judge 的分数是辅助观察，不单独触发当前硬门禁。报告延迟在 Judge 调用之前停止计时，Token 汇总包含回答与 Judge；这些口径不能混用。三轮估算成本均为不可用，不应写成零成本。

## 第三轮剩余失败

45 条可回答用例中，16 条返回固定拒答句。13 条在报告 Top 5 中包含全部预期文档；3 条文档召回不完整：`paraphrase-003`、`paraphrase-008`、`isolation-004`。

对前 13 条，缺少实际分片正文，不能全部判为“证据充分却拒答”。可能原因包括答案分片未召回、跨片综合不足、同义表达未识别，以及知识系统提示中的“内部过程/内部实现”限制被过度解释。上述是待验证假设，不是已经证明的模型根因。

`isolation-005` 另有如下不合格回答：

> 资料不足，无法确认。
>
> 旧格式向量缺少文档版本时是否仍可用于引用？

该回答没有引用，也没有回答“不能、重新导入”等事实；它违反固定拒答后立即结束的约束，分类器记为 `refused=false`。它不计入 16 条标准拒答，但也不能算作合格作答。应保留此失败记录，不能靠放宽分类规则修饰结果。

## 尚未解决的工程边界

| 问题 | 当前状态 |
|---|---|
| 流式输出边界 | 重复非空答案段冲突会抑制续段并清空最终净化结果，但已发出的 delta 无法撤回；生命周期未覆盖全部空正文/协议冲突状态 |
| 质量硬门禁 | 检查完整执行、异常、跨边界、无效/非同轮引用、禁止错误结论、Recall 回归和清理；未将空回答、事实命中率、过度拒答、所有格式违规纳入硬失败 |
| 无证据拒答 | 主要依赖提示词，尚无确定性的知识模式程序兜底 |
| 过度拒答 | 第三轮 16/45 标准拒答；知识规则与内部信息保护存在语义混淆风险，未完成分片级根因验证 |
| 证据观测 | 现有 JSON 只保留文档 ID 和聚合检查结果，无法还原具体模型输入和答案分片覆盖 |
| 检索拓展 | 没有 Hybrid Search、语义 Rerank 或相邻片段补回能力；5 份短文档的结果不能代表大型语料 |
| 部署与安全 | 租户 Header 上下文机制需要可信身份入口配合；本评测不是完整认证、授权或生产安全验收 |

硬门禁在第一轮有 25 条空回答时也通过，说明它侧重已有安全与回归规则，并不代表端到端回答质量合格。不得为收尾提高指标而放宽错误结论检查、引用白名单或租户隔离。
